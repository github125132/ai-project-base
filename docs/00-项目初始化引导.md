# 项目初始化引导(AI 必读第一步)

本仓为**通用基线项目模板**。任何新项目接入时,AI 的第一件事必须是**完成项目初始化**:把模板里的占位符替换为新项目的真实身份。

> 占位符是否已替换完毕 = 是否需要执行初始化。判定方法见下方"判定是否需要初始化"。

## 1. 判定是否需要初始化

满足下列**任一**条件即视为未初始化,必须先跑本流程,才能进入业务开发:

- 仓库根目录不存在 `project.config.yaml`
- 仓库内任意文档/代码中仍存在未替换的占位符 `{{PROJECT_CODE}}`、`{{PROJECT_NAME_CN}}`、`{{SUBREPO_BACKEND_DIR}}`、`{{DB_NAME}}` 等
- 子仓目录名与 `project.config.yaml` 中 `SUBREPO_*` 不一致
- `.env` 不存在(凭据未配置)

## 2. AI 交互式采集(用户只需回答 4 个问题)

> 不再要求用户手动编辑 YAML。AI 提问 → 用户回答 → AI 自动生成全部配置并执行替换。

### 第一步:问清 4 个核心字段

AI 向用户依次提问:

| # | 问题 | 字段 | 示例 |
|---|------|------|------|
| 1 | 项目短代码？(小写英文,用于目录/包/权限前缀) | `PROJECT_CODE` | `fire` |
| 2 | 项目中文全称？(显示在菜单、UI 顶栏) | `PROJECT_NAME_CN` | `智慧消防IoT管理系统` |
| 3 | 一句话描述？ | `PROJECT_DESC` | `临街商铺集群火灾实时监控与处置闭环平台` |
| 4 | 风格定位？ | `PROJECT_THEME` | `安全、高效、可视化` |

尝试从已有信息预填:
- 若根目录已关联远端仓库,从 remote URL 提取 `GIT_INTERNAL_GROUP`(如 `http://host/qnkj/repo.git` → `qnkj`)
- 若 `.env` 已存在,从中读取 `GIT_INTERNAL_HOST`、`GIT_INTERNAL_USER`
- 若子仓目录已存在(如 `gap-server/`),提醒用户确认新的目录名

### 第二步:自动推导其余 12 个字段

AI 根据 `PROJECT_CODE` 按以下规则推导,并向用户展示确认:

| 字段 | 推导规则 | 示例(PROJECT_CODE=fire) |
|------|----------|--------------------------|
| `PROJECT_NAME_EN` | `PROJECT_CODE` 大写 | `Fire` |
| `SUBREPO_BACKEND_DIR` | `{PROJECT_CODE}-server` | `fire-server` |
| `SUBREPO_ADMIN_DIR` | `{PROJECT_CODE}-admin-web` | `fire-admin-web` |
| `SUBREPO_APP_DIR` | `{PROJECT_CODE}-uniapp` | `fire-uniapp` |
| `BACKEND_MODULE_NAME` | `yudao-module-{PROJECT_CODE}` | `yudao-module-fire` |
| `BACKEND_PACKAGE` | `cn.iocoder.yudao.module.{PROJECT_CODE}` | `cn.iocoder.yudao.module.fire` |
| `API_PREFIX_ADMIN` | `/admin-api/{PROJECT_CODE}` | `/admin-api/fire` |
| `API_PREFIX_APP` | `/app-api/{PROJECT_CODE}` | `/app-api/fire` |
| `PERM_PREFIX` | `{PROJECT_CODE}` | `fire` |
| `DB_NAME` | `{PROJECT_CODE}` | `fire` |
| `DB_DUMP_FILE` | `{PROJECT_CODE}.sql` | `fire.sql` |
| `ADMIN_VIEW_ROOT` | `{PROJECT_CODE}` | `fire` |
| `ADMIN_API_ROOT` | `{PROJECT_CODE}` | `fire` |

> 用户可逐项覆盖推导值,不覆盖则直接确认。确认后 AI 自动生成 `project.config.yaml`。

### 第三步:生成凭据文件

1. 若 `.env` 不存在:从 `.env.example` 复制,自动替换 `{{DB_NAME}}` 令牌为 `DB_NAME` 的值
2. 若 `.env` 已存在但含占位符:只替换令牌字段
3. 敏感字段(`MYSQL_PASSWORD`、`REDIS_PASSWORD`、Git 账号等)如仍为占位符 `<...>`,提醒用户填写

## 3. 一键替换与验证(两条命令等价)

### 步骤 A:令牌替换

对仓库根目录及 `docs/`(排除 `docs/examples/` 和 `docs/00-项目初始化引导.md`)下所有 `.md`、`.yaml`、`.yml`、`.json`、`.gitignore` 文件,将下表所有令牌替换为 `project.config.yaml` 中对应值:

| 令牌 | 替换为 |
|------|--------|
| `{{PROJECT_CODE}}` | `PROJECT_CODE` |
| `{{PROJECT_NAME_CN}}` | `PROJECT_NAME_CN` |
| `{{PROJECT_NAME_EN}}` | `PROJECT_NAME_EN` |
| `{{PROJECT_DESC}}` | `PROJECT_DESC` |
| `{{PROJECT_THEME}}` | `PROJECT_THEME` |
| `{{SUBREPO_BACKEND_DIR}}` | `SUBREPO_BACKEND_DIR` |
| `{{SUBREPO_ADMIN_DIR}}` | `SUBREPO_ADMIN_DIR` |
| `{{SUBREPO_APP_DIR}}` | `SUBREPO_APP_DIR` |
| `{{GIT_INTERNAL_GROUP}}` | `GIT_INTERNAL_GROUP` |
| `{{BACKEND_MODULE_NAME}}` | `BACKEND_MODULE_NAME` |
| `{{BACKEND_PACKAGE}}` | `BACKEND_PACKAGE` |
| `{{API_PREFIX_ADMIN}}` | `API_PREFIX_ADMIN` |
| `{{API_PREFIX_APP}}` | `API_PREFIX_APP` |
| `{{PERM_PREFIX}}` | `PERM_PREFIX` |
| `{{DB_NAME}}` | `DB_NAME` |
| `{{DB_DUMP_FILE}}` | `DB_DUMP_FILE` |
| `{{ADMIN_VIEW_ROOT}}` | `ADMIN_VIEW_ROOT` |
| `{{ADMIN_API_ROOT}}` | `ADMIN_API_ROOT` |

**不替换**的位置:

- `docs/examples/` 目录下的所有文件(保留原 gap 演示供参考)
- `project.config.example.yaml`(本身就是令牌目录,不能动)
- `docs/00-项目初始化引导.md`(本文件,不替换)

### 步骤 B:目录调整

若子仓目录名与 `SUBREPO_*` 不一致,提示用户确认后执行目录改名。子仓是独立 Git 仓库,改名不影响 Git 历史。

### 步骤 C:最终验证

```text
[ ] grep 仓库内无未替换的 {{...}} 占位符(examples/ 除外)
[ ] grep 仓库内无 "gap" 误残留(若 PROJECT_CODE 不是 gap)
[ ] project.config.yaml、.env 均未被 git 追踪
[ ] 三个子仓目录名与 project.config.yaml 一致
[ ] 子仓内还是独立 Git 仓库(.git 目录仍在)
[ ] docs/README.md 的必读清单仍能链接到所有文档
[ ] .gitignore 中子仓忽略规则与 SUBREPO_* 一致
```

### 步骤 D:输出初始化完成报告

```text
项目代码: {PROJECT_CODE}
中文名:   {PROJECT_NAME_CN}
子仓目录: {SUBREPO_BACKEND_DIR} / {SUBREPO_ADMIN_DIR} / {SUBREPO_APP_DIR}
数据库:   {DB_NAME}
模块路径: {BACKEND_PACKAGE}
API 前缀: {API_PREFIX_ADMIN} / {API_PREFIX_APP}
权限码前缀: {PERM_PREFIX}:
```

## 4. 禁止事项

- 不得在本文档及 `docs/examples/` 中执行令牌替换
- 不得对子仓内部源码做大规模改名(子仓有自己的 AGENTS.md 与 Git 历史,改名走子仓流程)
- 不得把 `project.config.yaml`、`.env`、`application-local.yaml` 提交到任何远端
- 不得跳过交互确认直接进入替换
