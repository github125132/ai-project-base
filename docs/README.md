# 项目文档索引

`docs/` 保留长期有效的接手资料、项目要求、开发进度总览和功能级设计开发记录。

## 唯一权威必读顺序

AI 与新成员接手时按以下顺序阅读，**其他文档不再单独维护必读清单**：

### 阶段定位

| 阶段 | 文档 | 何时进入 |
|------|------|----------|
| 一、初始化 | `00` | 首次接入项目、占位符未替换 |
| 二、需求沟通与计划生成 | `06` | 初始化已完成、业务模块/Sprint/progress 仍为占位 |
| 三、子任务并行执行与 Git 自动化 | `07` | progress 子任务文档齐备后，循环执行直到收尾 |

### 必读顺序

1. 根目录 `AGENTS.md` —— 项目身份、仓库边界、不可变基础、三阶段工作流、Quick start
2. [00-项目初始化引导.md](./00-项目初始化引导.md) —— **若未初始化必须先执行**：占位符替换、子仓改名、配置生成
3. [01-项目要求.md](./01-项目要求.md) —— 业务模块、多端范围、UI 原则
4. [02-Git仓库初始化引导.md](./02-Git仓库初始化引导.md) —— 仓库策略、双远端、`.gitignore` 规则、提交规范（含类型表）
5. [03-数据库初始化引导.md](./03-数据库初始化引导.md) —— 数据库与 Redis 配置
6. [04-AI接手开发规范.md](./04-AI接手开发规范.md) —— 分层规范、状态字段、禁止事项、开发前自检清单
7. [05-项目开发进度总览.md](./05-项目开发进度总览.md) —— 当前阶段、模块状态、最近变更、风险
8. [06-需求沟通与项目计划生成.md](./06-需求沟通与项目计划生成.md) —— 沟通输入、子任务拆分规则、计划生成提交协议
9. [07-子任务并行执行与Git自动化.md](./07-子任务并行执行与Git自动化.md) —— 分支、并行、自动提交/合并/推送协议
10. `docs/progress/` —— 与本次任务相关的功能设计与开发记录
11. 涉及的子仓 AGENTS.md：
    - `ai-project-server/AGENTS.md`
    - `ai-project-admin-web/AGENTS.md`
    - `ai-project-uniapp/AGENTS.md`

## 文档维护要求

- 项目身份令牌见根目录 `project.config.yaml`；运行时凭据见 `.env`，两者均不入库
- `00`–`07` 八份根级文档分别处理初始化、项目要求、仓库、数据库、规范、进度、需求沟通、并行执行
- `05-项目开发进度总览.md` 记录整体阶段、模块进度、仓库状态、风险和最近变更
- `progress/` 记录功能级设计与开发过程，每个功能或阶段一篇子文档
- `examples/` 仅保留历史项目示例，**不参与令牌替换**
- 不保留零散临时流水账；开发记录必须沉淀为可追溯、可接手、可验证的长期资料
- 文档内容必须与 `AGENTS.md` 保持一致；若存在重复信息，以 `AGENTS.md` 为权威或互相链接，不复制粘贴
